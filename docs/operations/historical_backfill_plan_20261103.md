**2026-11-09 存储修订提示：本文的 100 字节/行、298 GiB 及 300～500 GiB 容量估算来自旧 ART+reference_price+TIME_NS 结构，已不再适用于当前库。当前生产库经重建为 14.1 GiB；后续容量预算必须使用新 Schema 的实测增长，并同时计入恢复点，不得沿用上述旧估算。**

## 1. 首轮范围与三条执行轨

首轮固定范围为 **2013-01-01～2026-10-30**，按现有 SSE 日历处理，首个开市日为 **2013-01-04**。将截止日固定在已验收的锚点，避免历史任务不断追逐移动终点；2026-11-02 起的新增日期另开增量窗口，仍逐步确认执行。

| 数据类别 | 处理方式 |
|---|---|
| stock_basic、index_basic、index_member_all、bse_mapping | 复用现有完整快照，不把它们误当逐日历史快照；同一 A/B/C 窗口内不刷新 |
| trade_calendar | 2013～2026 已发布，核对目标区间 Coverage 后复用 |
| suspend_daily、stock_st、stock_daily、daily_basic、adj_factor、stk_limit | Tushare 全市场逐日获取，CLI 先按自然月组织；不按当前股票快照裁剪日集合 |
| index_daily | 单独执行，先试一个自然月，再按自然年组织，利用现有宽基代码年片及申万逐日请求；不改变零行契约 |
| stock_1min | 银河直连；先受控 Pilot，再按批准的小日期窗口回补；分钟只依赖日历、股票基础、北交所映射、停复牌和股票日线 |
| index_weight | 独立的延迟数据轨，先确认各指数实际可用日期范围，再用现有日期／指数子集入口回补；不阻断分钟或行业 Serving |

沪深分钟从 2013 年起，北交所下界沿用 2021-11-15 及证券在市日期。2026-11-05 起 Scope/Canonical 全历史统一使用 n_code；银河改代码前请求可在 Adapter 内路由 o_code，响应统一回 n_code。旧 Raw 和 2010～2012 文件已经按用户后续决议删除，不再按旧提案的“保留本地历史”文字执行。

当前 stock_basic 快照通过 list_date／delist_date 派生历史 membership，并不保证完整 PIT 或供应商遗漏的历史证券覆盖。本方案的全量是“按现有已确认契约确定的范围”，不引入新的证券历史模型。历史行业断档仍保留 NULL，不为通过 Serving 测试填补归属。

## 2. 规模与资源预算

以下为本机只读测算，不是供应商全历史可用性承诺：

| 项目 | 当前证据／推算 |
|---|---|
| 目标区间开市日 | 3,355 日 |
| 当前股票快照推导的在市股票日 | 约 1,328 万；未扣除未知冲突，也未确定实际请求集合 |
| 连续分钟网格 | 约 31.88 亿行 |
| 加每股票日最多一行竞价 | 上界约 32.02 亿行；全天停牌及零竞价不会实际增加该行 |
| 已成功单日 | 5,577 Unit、1,344,709 行，5,599 次请求，555.7 秒 |
| 当前完整库 | 128 MiB，含该分钟日、其他事实、索引及 Meta |
| 粗略容量参照 | 按当前整库约 100 字节／分钟行等比外推，约 298 GiB；不是分钟表独占大小或实测全历史结果 |
| 当前运行环境 | 内存约 15.5 GiB；DuckDB 默认上限约 12.3 GiB，但 Python／Polars 内存另占；文件系统报告可用约 931 GiB |

不能由一个交易日承诺最终库大小或完成时间。先以工作库约 300～500 GiB 做预算敏感性分析，在累计 20 个新交易日后重估索引、Meta、暂存和备份占用；宿主物理存储余量也需在放量前核验。先保留至少 64 GiB 的暂存／失败证据余量，实际下批数据需求更大时相应上调。

若始终单日全市场执行，K 线请求在扣除全天停牌前约 1,328 万次，快照请求按当前 membership 估计上界约 6.8 万次。按当前股票日耗时简单等比的参照约 370 小时，不能作为工期承诺。多日请求能减少调用数，但不能等比例减少交付字节、准备开销或周流量。

## 4. 批次规则与推进顺序

1. **分钟先一日，验证后两日；三个至五个交易日仅按实测逐级批准。** 默认并行度 2，不自动升到 4。暂不采用十日全市场 Run。
2. 每批记录父进程与 worker 的合计 RSS、系统剩余内存、取数／准备／发布耗时、库增长和暂存峰值。扩大窗口的建议条件：进程树峰值不超过 8 GiB，系统可用内存保持至少 4 GiB，fetch 不超过 30 分钟；否则缩小窗口。仅看单个子进程 MaxRSS 不能当作总峰值。
3. 现有 worker 每轮硬超时为一小时；这些建议阈值预留余量，不修改执行层超时或熔断机制。开始新批前检查预计新增数据、临时证据、备份所需磁盘空间，不满足预算即暂停放量。
4. Pilot 及门槛确认后，按自然月作为人工验收窗口，先完成 2026-10，再按月倒序至 2013-01。每个月内部用已批准的一至两日等小窗口执行分钟，不把整月直接传入分钟 CLI。当前参考价由当日日线初始化，不依赖前日分钟，允许按此顺序回补。
5. 完整成功的既有日期先核对 Scope、Coverage 和版本再从普通补缺计划中排除；首次试点或明确修订可显式重跑。不能只看全库最大日期判断完整。
6. 窗口开始前复用并核验四份快照；有必要刷新时放在新窗口开始前，并记录实际版本。同一窗口内不刷新，不让另一个 agent 或研究进程同时写库。已完成窗口保留其真实依赖审计，不暗中实现全历史失效传播。

**十日分片是单只股票 K 线请求上限，不是 CLI 内存批次上限。** 当前 Adapter 会汇总整个 Run 的 Python 行对象、Raw 与 Candidate；按年运行分钟可能先耗尽内存。遇到容量上限时先报告和讨论，不临时改成股票分片或新增 CLI 子集接口。

## 5. 每个验收窗口的 A/B/C 分工

| 阶段 | 执行者与动作 |
|---|---|
| A：代理开启 | 协调 agent 获取目标范围的六项股票日频；index_daily 按其单独年度／月度任务获取；确认分钟真正需要的 stock_daily 和 suspend_daily Coverage 完整，解析 Scope 并给出固定命令与日志路径 |
| B：代理关闭 | 可直连的执行 agent／本地终端只运行批准的分钟日期窗口，单账号单会话，串行访问同一权威库；JSON、stderr、退出码分别留存；不夹带权重任务 |
| C：恢复代理 | B 结束并释放连接后，协调 agent 核对请求、Unit、Publication、Coverage、固定依赖和分钟规则；每个自然月窗口结束运行 dbt build，并按日统计行业未匹配；首个历史日即运行一次 Serving 验收 |

不为每只股票或每条命令切换代理；在资源允许的窗口内完成一批 B 任务后统一交回。生产源库始终为 `data/warehouse.duckdb`，不再新建长期验证库或第二份分钟业务存储。

## 6. 失败与恢复

- PARTIAL／FAILED 均停止当前执行批次并交回日志；已发布 Unit 与成功指针保留。默认 SUCCESS 清理请求暂存，失败证据保留。生产 `stock_1min` 回填和修复禁止 `--keep-artifacts`：它包含整张 Canonical 与全阶段快照导出，流式哈希不降低该部分耗时或磁盘成本；完整 walkthrough 只用于规模受控的独立库。
- 仅有当前 Run 内的证据恢复，不承诺跨 Run 断点续传。银河分钟可重复传 `--ts-code` 显式补选股票日，其他股票不产生本次请求或发布；本地 Parquet 仍没有子集入口，重跑会重发该日全部成功 Unit。两种方式都只替换目标 Unit，并产生新的发布版本。
- 配额／服务熔断遵循现有 `-82/-78/-91` 规则；触发后停止，不踢会话、增加并发或无限重试。其他查询时段、频次及网络错误分别记录并排查。
- 冲突、缺字段、截断、异常停牌格式或未知 Scope 都按现有契约报告，不通过清库、填造记录或放宽规则换取成功。
- 用普通日期清单与现有 Meta 记录完成窗口和缺口，暂不引入任务数据库、调度器或自定义水位线体系。
- Meta 明细按 **Run 结束时间** 执行既有 60 天归档／365 天允许过期规则，不因行情日期是 2013 年就清理刚产生的回补审计。

## 7. 指数权重独立安排

供应商约一个月滞后是用户已确认的现状，不转换成“当天减 30 日必然可取”的规则。先以既有成功日 2026-09-07 验证五指数当前可取，再分别确认各指数可用区间；不假定五个指数的权重都从 2013 年起存在。

使用现有 `--index-code` 和日期区间，单指数单日请求；该轨暂按每批最多五个交易日执行。遇到空交付仍失败并保护旧事实，结束该批后确认是延迟、历史覆盖还是其他问题，不跨数千个未知空日期盲扫。2026-10-30 五个 FAILED Unit 继续保留，后续仅在供应商实际提供该日数据后显式补取。

## 8. 配额、容量复核与备份

Tushare 的六项股票日频在既有分页契约下粗估约 2.0～3.0 万次请求，index_daily 若按自然年合并约 3,691 次，合计约 2.4～3.4 万次，实际取决于历史页数和重试。沿用当前串行间隔，账号实际额度未核验；频次与权限以[官方权限表](https://tushare.pro/document/2?doc_id=290)及实际账号为准，不将一般表格当成本账号额度。

银河已知存在流量／查询配额，但本次未查明本账号剩余额度、重置点或全历史所需流量。依据锁定 SDK、[既有性能探查](../research/galaxy-perf-probe-2026-10-19.md)及本次实测规划，不给出虚假的完成日期。

保留已验证的 128 MiB 回补前备份；第一个历史日完成后做一次阶段备份，之后在自然月验收点安排滚动备份，不为每个分钟小批复制整库。新备份核验完成后再处理旧阶段备份。容量复核必须同时计入工作库、旧／新备份可能共存的峰值和暂存余量；若空间不足，先确认备份位置或缩减执行窗口，不自动删除已验证备份，也不改冻结存储架构。
