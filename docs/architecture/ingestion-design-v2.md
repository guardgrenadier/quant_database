# Ingestion 设计决策集 V2

状态：**现行有效**。2026-09-23 至 2026-09-25 设计讨论中由所有者逐点拍板形成，取代旧 V1 设计（`overview.md`、`ingestion-framework.md`、`minute-data-ingestion.md` 三份已冻结保留，见 §11）。

实测依据：`docs/research/minute-api-request-experiments.md`（含 2026-09-23 补测）、`docs/research/tushare-proxy-official-examples-2026-09-19.md`、`benchmarks/decimal_vs_double/REPORT.md`。

## 0. 设计原则（invariants，所有者原话要点）

- I1 pipeline 与具体 API 解耦：换源修改范围要小；允许不同 dataset 来自不同源。
- I2 三层存储：raw → temp parquet → canonical parquet view。
- I3 第一层尽可能少做校验：忠实落盘 API 返回的原始数据；负价格这类业务异常不是 API 失败、不阻塞；第一层只确保当天的接口数据被忠实地拉取下来。
- I4 第一层发布后，下游信任抓取完整性、不再复查；语义检查和数据质量检查由后两层（dbt）负责。
- I5 先获取当日全部交易股票，再拉取（universe-first）。"分批（每批 10 只）"的读法已被 D1 取代。
- I6 简单、透明、可重建；单机个人研究环境；反对提前抽象。

## 1. 数据集拓扑

四个一等 dataset，各自有独立的 raw → canonical 路径与发布（D2/D3/D4）：

| dataset | 形态（D5） | 保留/更新 |
| --- | --- | --- |
| `stock_basic` 快照 | 快照类 | 每日全状态（L/D/P 等）快照，覆盖写 |
| `trade_cal` 日历 | 快照类 | 每日最新快照，覆盖写 |
| `suspend_d` 停牌 | 日频事实类 | 按 trade_date 逐日累积 |
| `stk_mins` 分钟 | 日频事实类 | 按交易日累积发布 |

- universe（stock_basic）是与 minute **平级的 dataset pipeline**，编排上先于 minute 运行；minute 读其产物（D2）。
- universe 快照与 minute 抓取均安排在**收盘后**运行（D7；依据：盘后快照已含当日新股，供应商行情约 15–17 点更新）。
- universe 等一等 dataset 同样适用 I2 三层与 I3/I4 契约：minute 信任其发布产物，不复查。

## 2. 抓取（L1）

### D1 抓取单元与编排（2026-09-23 拍板）

- 切片 = **一只证券 × 一个交易日**，单独请求；**拒绝多代码批量**（实测：2 代码批次补数超 53 分钟未推进，单代码约 10 分钟；批次与单代码是各自缓存键；多代码 limit/分页语义未验证）。
- 最多 8 并发、全局 ≤180 次/分（低于实测 IP 200 次/分限制）。5533 切片/日，理论下限约 31 分钟，估 45–90 分钟。
- pending（HTTP 202 `minute_data_pending`）**不在 run 内等待**：记录后留待后续轮次收敛（重申旧拍板 P2）。依据：补数耗时实测 10 分钟到 50+ 分钟不可控。
- **D24**（2026-09-30 拍板）：抓取窗口由 `09:30:00–15:00:00` 拓宽为**全天** `00:00:00–23:59:59`（与 date-only 形态实测等价）。动机：让 15:01 等窗外异常进入 core 外检测的可见边界；已知代价：盘前竞价与盘后填充回流 canonical、行数更飘、与网盘历史段（紧窗）存在覆盖接缝。观测期后若全天窗无新增信息，可回退紧窗。

### D6 universe 会员谓词（2026-09-24 拍板）

切片集合 S = universe 全状态快照 ∩（`list_date ≤ t < delist_date`，delist_date 空视为 ∞）∩（当前 status ≠ P），**统一当日增量、隔日补抓、历史回补三场景**。D2 的"minute 读 L"被本谓词取代。

依据（2026-09-23 补测）：左端含经 IPO 当日分钟数据正例确认；`delist_date` 是摘牌日而非最后交易日，最后交易日不可由 `delist_date - 1` 推断；**边界外请求形态危险**（摘牌日零量骨架、退市后机械复制的陈旧非零填充、或长 pending）——HTTP 200 / 非空 / vol>0 均不能证明边界外数据合法，必须在请求计划阶段排除。排除当前 P 是保护（P 请求形态未实测）；代价是历史上"当时处于暂停"不可还原，误差方向为少抓本无交易的日子。

### 完整性定义（"当天数据被忠实完整拉取"，2026-09-24 拍板，谓词随 D6）

**忠实半边**：raw 保留响应原文，不修补、不筛除、不换算，重复行也原样保留。进入 temp 时，才允许对内容完全相同的重复行按主键 `(ts_code, trade_time)` 去重。同主键冲突值不得取首/末条——切片不得标完成，阻止发布、人工检查。

**完整半边**（只看本地记录判定）：

0. 计划先固定再抓取：t 经 trade_cal 产物判 `is_open=1`（闭市日不产生计划）；S 按 D6 谓词生成 × 固定窗口 `00:00:00–23:59:59`（全天，D24）× 固定参数（freq/fields/limit/分页规则），抓取开始前落账。
1. 每切片三终态：**有数完成**（分页按"末页 < limit"终止，每页 HTTP 200 且 code=0，重复页/游标不前进/超页数三保护未触发）；**空完成**（200 + code=0 + 0 行的终态响应即判合法空——含首次请求即返回空、未经 pending 的情形；pending 未收敛不得判空。2026-09-29 所有者确认此读法）；**未决**（其余一切）。
2. t 完整 ⇔ S 中无未决切片；且返回行全部落在请求的代码×窗口内（逐行校验，不只看状态码——stock_st 曾返回范围外日期）；主键无重复或重复行完全一致。
3. 行数不参与判定（实测合法单日 241/249/250/281 不等；停牌日 241 根零量骨架属有数完成）。

**明确不包含**（= I4 下游信任的边界）：供应商是否覆盖全部应交易证券（不可证）；快照/谓词的残余盲区；值的业务正确性（归 dbt）；供应商事后修订（归刷新策略 D16-7c）。

## 3. raw 层

- **D8**（2026-09-24 拍板）：每切片一个文件、**JSON 原文（gzip）**、写一次不可变（唯一例外见 D16-7b 整切片替换）。多页切片的文件内容是 JSON 数组：按页序放入各次成功响应的原始 JSON 字节，仅在外层添加数组分隔符；单页也使用相同格式。请求参数、页序、抓取时间和响应状态另记在切片账/过程日志。分页完整结束并通过 L1 契约检查后，才将临时文件原子替换为正式 raw 文件；pending/失败保持未决，冲突或契约违背的响应进入 quarantine。temp parquet 为运行期临时产物，无保留语义。
- **D9**（2026-09-24 拍板）：raw 保留 **30 天**后删除；护栏：按实际抓取时间计期、对应 canonical 发布确认后才删、未发布/失败批次豁免。四个 dataset 同策略。**明确接受的后果**：审计断源（账在、原始响应不在）；30 天后重建锚点移至供应商重取/canonical；universe 快照史不保留；canonical 成为唯一长期数据资产。
- 例外：**网盘原始历史文件永久保留**，划出 D9 范围（D17-8b）；实物是按年目录、逐交易日 Parquet，见 [勘察报告](../research/historical-parquet-survey-2026-09-29.md)。

## 4. 记账与审计

- **D10**（2026-09-24 拍板）：状态账三表（计划 / 切片 / 发布，DuckDB，长期保留）+ 过程日志 JSONL（按 run 存放，30 天随 raw 清理）+ quarantine 隔离区（冲突/契约违背留证，豁免清理至人工关闭）。计划即插入（status=planned）、抓取即状态迁移、完整性判定即一条 SQL。写方仅 ingestion / publisher / 清理器；**dbt 不读状态账**。
- **D20**（2026-09-29 拍板）：quarantined 切片允许被后续 run 自动重抓（不排除出未决集合）；但**曾 quarantined 而后成功**的切片，在该日发布时须向 quality_findings 写一条 warn（含切片标识、原冲突/违约摘要、quarantine 证据指针）——自愈不得静默。重抓仍违约则切片维持未完成、当日不发布；quarantine 证据仍豁免清理至人工关闭。
- **quality_findings**：第四张长期表（D13 拍板）。dbt 判定语义告警并保存本次失败行；publisher 在发布前把检查名、dataset、trade_date、run_id、异常数量及少量样例写入长期账，按 run_id 与检查名幂等。历史告警不因后续重跑覆盖。dbt 不读写状态账；publisher 是 quality_findings 的写方。
- **D22**（2026-09-30 拍板）：quality_findings 粒度细化为（检查项 × dataset × trade_date × ts_code 可空），severity 扩 error 档；publish 流程**先落 findings 后判定阻断**——结构阻断也以 error 级落账，被阻断的日子同样积累证据。
- 发布账内容：dataset、trade_date、阶段迁移+时间戳、发布行数、transform_version（git commit；未提交修改不得冒充干净 commit）。发布后替换不留旧版本字节，diff 摘要（行数差、主键差集规模、样例）写 quality_findings——**字节不留，事实留痕**（D16-7e）。
- 账本库与 canonical 并列为"唯二长期资产"；备份策略为登记中的运维项。
- **D18**（2026-09-29 拍板）：账本库文件物理独立——dbt 不得以账本库为工作库，消费视图等可重建派生物不得在账本库文件内物化。待实施：dbt profile 与视图落点拆分（评审发现当前 `minute_bars` 视图物化在账本库内）。

## 5. canonical

### D11 行政策（2026-09-24 拍板）

canonical **窗内全量保留**：含 09:30 开盘集合竞价 bar、午间不规则填充 bar、停牌零量骨架；D24 后另含盘前竞价（09:25–09:29）与盘后填充 bar（网盘历史段为紧窗口径，与全天段存在覆盖接缝）；过滤只发生在 view。默认 view = **纯连续竞价** `bar_time ∈ (09:30, 11:30] ∪ [13:01, 15:00]`（排除 09:30——所有者认定其为集合竞价量——及午间填充）；停牌骨架**留在** view 中，消费侧按 vol=0 或 suspend_d 识别。重申旧拍板 P4。

### D12 列政策（2026-09-24 拍板）

| 列 | 类型 | 口径 |
| --- | --- | --- |
| `ts_code` | VARCHAR | **保留源名**；含交易所后缀 |
| `trade_time` | TIMESTAMP（无时区） | 解析源字符串，保留供应商 bar 时间标签（上海本地） |
| `trade_date` | DATE | 从 trade_time 派生 |
| `open/high/low/close` | DOUBLE | 未复权；依 decimal/double 基准结论（Decimal 导出慢 1.72x、精度差异 ≤1e-7 不影响研究） |
| `vol` | BIGINT | 股；保留源名 |
| `amount` | BIGINT | **单位：分**；源 JSON 数字单位为元，按十进制值计算 `源值 × 100`，再明确按 half-up 规则舍入到整数分并转 BIGINT，避免先转 DOUBLE 导致临界半分误差。源值为负在舍入前告警、不阻止发布；无法解析、非有限值或转换后溢出则阻止发布。吸收并修订旧拍板 P3 |
| `extracted_at` | TIMESTAMPTZ（UTC） | 抓取侧生成、dbt 重跑不改；仅网盘历史允许为空 |
| （`freq`） | — | 校验 = `'1MIN'` 后不存储（dataset 属性） |

主键 `(ts_code, trade_time)`。**D25**（2026-09-30 拍板）：`open/high/low/close/vol/amount` 允许 NULL——供应商内容异常不阻断（集成实测：单只票可出现大量 close-only bar），NULL 行原样进 canonical，由 D23 告警与 D22 日×股票落账留痕；收窄后的阻断清单见 §6。消费 view 再映射为 `secu_code`/`volume`，并派生 `bar_time/date_int/time_int`（不物化）。不引入 `pre_close/change/pct_chg` 等特征列。

## 6. 检查体系（2026-09-24 拍板，D13/D14/D15）

**失败语义两级**：结构/契约类失败 → **阻止发布**（转换不可信）；业务语义异常 → **发布照常 + 告警**（落 quality_findings）。依据：I3 + D11——canonical 反正全量保留，语义检查没有"阻止"的合法对象。

**分层原则**：每层只查本层新引入的风险（L1 协议合规 / L2 转换正确性 / L3 view 逻辑 / publisher 跨边界对账），以此根除重复检查。

**L2（dbt）阻止发布清单**（D25 收窄后）：必需**列**齐全（列存在性，防协议漂移）且 `freq='1MIN'`；主键字段（`ts_code`、`trade_time`）非空；类型转换成功（amount 不可解析、非有限或溢出阻止；**OHLC/vol/amount 为 NULL 不阻止**，见 D25）；主键合并后唯一；行数对账（raw 去重后 = canonical，D11 的可执行形式）；**管道完整性检查**（canonical 行 ∈ 计划 S×目标日——正名保留，防错文件/串日，与 L1 越窗检查不正交但防的失败模式不同）；发布阶段文件可读、日期与路径一致。

**L2 告警清单**：OHLC 关系违反；负价格/负量/源成交额为负（成交额在舍入前检查，避免微小负值舍入为 0 后漏报；负量额不阻止发布）；零量整日与 suspend_d 交叉不一致；填充 bar 占比与行数分布离群（追踪上游是否修订填充）；单日 empty 切片数异常（publisher 侧，读切片账）。

**观察期模式告警**（D23，2026-09-30 拍板；纯告警、按日×股票落账、不影响发布）：close-only bar 计数（OHLC/vol/amount 空、close 非空）；09:30 与 15:00 边界 bar 字段不全；core 外 bar 检测——trade_time 落在常规 241 根集合（09:30–11:30、13:01–15:00）之外的 bar，记录其时刻清单（如 13:00），只记录事实、不作成因揣测。

**挂层**：数据质量检查全部挂 L2 canonical 全量跑一次；**L3 只挂 view 契约测试**（如"默认 view 无 09:30 行"），不测数据——L3 挂法的结构性盲区是 view 恰好滤掉了最可疑的行（填充/竞价），且填充类检查在 view 上无法执行。

**框架分工**：数据检查在 dbt 内（test severity error/warn 映射两级；告警测试保存本次失败行，但测试产物不充当长期审计账）；publisher（Python）负责持久化 quality_findings 和读取状态账做跨边界对账，dbt 不读状态账。

**明确不做**：不强制固定 bar 数；不与日线/其他源对账量额；不要求价格大于零（实测存在 open=0 真实行）；特征层检查待特征存在再定（I6）。检查范围限定本次处理日期，不重复扫全历史。

## 7. 发布与重跑（D16，2026-09-24/25 拍板）

- **7a** 发布单位 = dataset × 交易日；候选文件在 canonical 读取路径**之外**生成 → 检查通过 → 同文件系统替换正式日文件 → 发布账登记。
- **7b** 重跑语义：发布前重跑只补未决切片、已 ok 切片不重取；发布后重跑**整日替换**不追加（已完成切片需重取时整切片替换——D8 不可变性的唯一例外）；转换侧重跑（dbt 逻辑变更）只从 raw 重建不重抓（受 D9 30 天窗限制）。
- **7c** 刷新策略：**观察期**——发布后次日（T+1）重取当日并 diff，先跑约两周，统计差异率后据实测定常态策略（所有者原话要点："先观察看看在每天较晚时间抓取是否安全"）。回应实测遗留：当日数据完整时点与事后修订未知。
- **7d** 失败恢复：抓取中坠机按切片账续跑；替换后登记前坠机以**文件系统实际状态为准**核对后补登记或安全重做（账本不做假设）；转换失败未发布 → raw 豁免删除、修后从候选重建；canonical 已发布而下游失败 → 从已发布数据补算，不重抓。
- **7e** 发布账与修订留痕：见 §4。审计面 = 状态账 + quality_findings + 发布账/修订留痕（#9 关闭）。

## 8. 历史数据（D17，2026-09-25 拍板）

- **8a** 网盘历史（按年目录逐日 parquet，截至 2026-04-17）跳过 raw 层、从 temp 层进入，走同一 L2 检查与候选→替换→登记机制；一次性脚本，不建长期历史适配框架；入场前置 = **勘察报告**（schema 映射、时间口径、覆盖范围）。
- **8b** 网盘原始文件永久保留（见 §3）。
- **8c** 历史日完整性不套用抓取判定，代以：勘察 + **重叠期 API 重取抽样逐行对比**（定信任级别）+ D6 谓词覆盖率对照（warn 级，缺口不阻塞但留痕）。批量发布门禁必须验证信任报告 `trust_level == sampled_match`；`low_or_pending` 拒绝批量 `--apply`，仅允许 `--limit-days` 试点并人工抽查（**D21**，2026-09-29 拍板）。
- **8d** 行内不加 `source` 列；发布账按日记录来源（网盘/API）。
- **8e**（2026-09-29 修订）gap（2026-04-18 至起跑日）：规划上按 ≤7 连续交易日分段（跳过已发布日、不越日历快照年），HTTP 保持单代码×单日逐日抓取、复用日增链路（抓取窗口随 D24 全天）——单日是 D1 唯一已验证形态；原"≤7 日跨日窗口 + 逐行裁剪"方案降级为未验证优化，需要时单独评估。`--probe-code` 单代码复测为建议、非强制前置；**排序在日增链路跑通之后**。
