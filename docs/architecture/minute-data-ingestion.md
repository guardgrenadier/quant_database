# 股票分钟数据 Ingestion 设计

状态：已废止（冻结保留，2026-09-25）。现行设计决策见 [ingestion-design-v2.md](ingestion-design-v2.md)；与 V2 冲突处以 V2 为准。2026-09-21 整合原 minute-data-processing 与 minute-pull-strategy 两份文档，并按同日设计讨论修订（分页归 adapter、pending 多 run 收敛、amount 舍入口径、view 过滤无效行）；2026-09-23 补测结论（会员谓词、退市边界行为）收录于本文。实测依据见 [../research/minute-api-request-experiments.md](../research/minute-api-request-experiments.md)。

## 目标与流程

当前覆盖股票 1 分钟行情，未来按实际需求扩展指数、ETF。长期只保留一份完整分钟明细；原始响应仅作短期缓存。

```text
API
 ↓
raw temp Parquet（原样字段、抓取元信息、manifest，缓存 30 天）
 ↓ dbt 标准化与检查
canonical Parquet（全部 bar，包含 09:30 与填充 bar）
 ├─ 消费 view：过滤 09:30 与连续竞价时段外的无效行，生成便利用列
 └─ dbt 日频特征：按需读取全部 bar，结果写入 DuckDB 表
```

Python ingestion 负责请求计划、抓取编排、缓存落盘与发布；dbt 管理转换与检查。文件发布与缓存清理由薄的流程脚本负责，不引入通用调度框架。

## 源与切片

当前源为 ProMax 网关 `stk_mins`（provider=external）。不使用 `a_share_mins`（实测每 bar 重复约 8 次、时间带毫秒后缀，且与 `stk_mins` 是不同数据层，不可拼接）。

切片 = **一个证券 × 一个交易日**，这是唯一已实测验证的形态。

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 窗口 | `start_date=YYYY-MM-DD 09:30:00`，`end_date=YYYY-MM-DD 15:00:00` | 双端包含；对齐历史 canonical 的 09:30 起点，排除盘前竞价（09:25–09:29）与盘后填充（15:01+） |
| `freq` | `1min`（显式传） | 实测 `1min`/`1MIN`/省略结果一致，官方文档必填 |
| `fields` | `ts_code,trade_time,freq,open,high,low,close,vol,amount`（显式固定） | 固定字段避免分页间字段漂移 |
| `limit` / `offset` | 500，从 0 起每页 +500 | 当前单日 241–约 300 行，通常一页取完；分页作兜底 |
| 顺序 | 顺序请求，不并发 | IP 限流 200 次/分；避免触发并发补数 |

每证券每日预期 1 次请求（偶发分页 +1）。全市场 5533 只约 5533 请求/日，限流下稳态约 30–90 分钟；首批全市场抓取会触发大量服务端补数，不按此时长估计。

暂不采用：

- **多代码批量**：limit 作用域与分页语义未验证；实测批次补数超过 53 分钟未推进，且与单代码是各自的补数任务。如需启用，先单独验证。
- **盘前竞价 bar（09:25–09:29）**：与历史 canonical 的 09:30 起点口径不一致，不纳入切片；未来需要时单独评估。

## Adapter：分页与切片终态

分页是 adapter 的内部职责（见 framework）。对 `stk_mins` 的实测规则：

1. 固定 `limit=500`，`offset = 0, 500, 1000, …` 顺序取页。
2. **终止（ok）**：某页 HTTP 200、`code=0` 且行数 < `limit`。0 行页是合法终止页；恰好满页必须再取一页。
3. **终止（failed）**：某页与上一页主键集合完全相同且非空（重复页）；游标不前进；页数超过 20；任何非 200 / `code!=0` 响应。
4. 切片完成后协议校验：并集主键 `(ts_code, trade_time)` 无重复；`ts_code` 等于请求代码；`trade_time` 落在请求窗口内。同一主键出现冲突值时不得取首条或末条，切片标 failed。
5. 不依赖排序承诺：合并按主键去重，分页有效性依赖 offset 语义而非顺序假设。

切片结果四态：**ok / empty / pending / failed**。`empty` 只表示 200 + `code=0` + 0 行，其合法性由 pipeline 判定。

## pending 与失败：多 run 收敛（已决策）

- HTTP 202 `minute_data_pending`（带 `Retry-After: 30`）**不是错误也不是空结果**。实测补数耗时不可控：热代码约 10 分钟；非交易日约 48 分钟后转为合法空结果；上市前日期与多代码批次超过 50 分钟未解决。
- **run 内不等**：切片 pending 即记录状态继续下一个；run 收尾不统一重访（旧的 15 分钟预算 + 收尾重访策略已废弃）。未完成切片留给下一次运行，服务端补数可能已完成，重访通常是一次缓存命中。
- 空结果只在 200 响应上判定；长时间 pending 既不是空结果证据，也不是失败证据。
- 429：读 `Retry-After`，自限速 ≤180 次/分（IP 上限 200）。
- 503：两种实测形态——带 JSON 的 `upstream_pool_exhausted` 与无 JSON 的裸 503（网关级，实测约 3.5 分钟自愈）。wrapper 内有限重试（分钟级预算），仍失败则切片标 failed。
- 400 `invalid_params`：不重试，检查参数。

## 请求计划与证券集合

- `trade_cal` 确认交易日，闭市不发起请求。
- 证券主数据快照使用已验证的单页形态：`stock_basic(list_status='L,D,P,G,UN', fields='ts_code,symbol,name,exchange,market,list_status,list_date,delist_date', limit=10000, offset=0)`。2026-09-23 实测 5917 个唯一代码（L 5568 / D 339 / UN 10，P/G 当日为 0），339 个 D 的 `delist_date` 全部非空；响应必须检查固定字段、代码唯一、状态枚举和行数严格小于 limit。
- 每日增量和历史补抓统一从该快照按日期生成集合，不能只用当前 L（幸存者偏差）。边界为左闭右开：`list_date <= 目标日` 且（`delist_date` 为空或 `目标日 < delist_date`）。上市首日分钟已有正例；`delist_date` 是摘牌日而非最后交易日，摘牌日／之后请求实测会 pending、返回零量骨架，甚至返回机械复制最后一根量价的非零假数据，必须在计划阶段排除。
- D 三交易所计数（SSE 147 / SZSE 187 / BSE 5）与全状态 D 子集逐行闭合，6 只跨市场／年代样本均存在，4 只摘牌日期与公司公告一致；尚不能由有限抽样证明全历史覆盖，但本轮没有发现已知缺口。最后交易日可能早于 `delist_date` 多日；需要“实际成交日”时另查日线／停复牌／公告，不能用 `delist_date - 1` 推断。
- 证券集合快照与请求清单一并存入 raw manifest，作为完整性核对基准。
- 停牌日实测返回 241 根零成交量骨架 bar（**非空响应**），全量进 canonical；是否停牌用 `suspend_d` 交叉标记，不靠行数或零量推断完整性。

## raw temp 层

- "raw 原样"指保留 API 返回字段和值、不做业务清洗，不要求逐字节归档 HTTP 响应；wrapper 把响应整理为记录，但不决定数据如何入库。
- 布局：`data/raw/stk_mins/trade_date=yyyymmdd/` 下每切片一个 parquet，外加 `manifest.json`（请求计划、每切片状态与行数、实际抓取时间）与 `requests.jsonl`（逐请求脱敏摘要）。不为每个 HTTP 请求建数据库记录。
- `extracted_at` 由抓取侧生成（UTC），随缓存保存，dbt 重跑不改变。
- 用显式 arrow schema 写文件（adapter 声明期望字段），避免跨文件类型推断漂移——这是协议对齐，不是语义检查。
- 逐切片落盘，中断后按 manifest 续跑。
- 保留期按实际抓取时间计算，不按行情日期；满 30 天且对应 canonical 已成功发布后才能删除；失败批次不因到期删除。缓存到期规则不作为删除网盘原始历史文件的依据。

## 整日完成（fetched gate）

1. 请求计划固定：交易日确认 + 证券集合快照落盘。
2. 全部切片 ∈ {ok, empty}，无 pending、无 failed 残留。
3. empty 分类：良构计划下 empty 几乎不该出现（闭市已在计划阶段排除、未上市已由证券集合排除、停牌返回骨架而非空）。empty 如实记录进 manifest，**不阻塞**；单日 empty 数量异常时告警，人工检查。
4. 满足后进入 raw → canonical 候选与发布；否则整日不发布，保留 raw 供多 run 收敛。

以上证明的是"按接口协议抓完"；供应商是否覆盖全部应交易证券依赖供应商承诺，接口层无法证明。

每日处理流程：

```text
day = 目标交易日（trade_cal is_open）
codes = universe(day)                        # 快照落盘
plan = [(code, day) for code in codes]
manifest.open(day, plan)
for code in codes:
    if manifest.terminal(code): continue     # ok / empty 已完成，跳过（恢复）
    result = source.fetch_slice(code, day)   # adapter 内部完成分页与协议校验
    manifest.record(code, result)            # ok → 写切片 parquet；其余记状态
if all slices ∈ {ok, empty}:
    mark fetched
    dbt 生成候选日文件并检查                  # 失败保留现场，不发布
    替换正式文件、登记发布
    dbt 重算目标日期日频特征 → 登记结果
else:
    不发布，退出；下次运行续跑收敛
```

## Canonical

标准化后的 Parquet 是长期唯一分钟明细。按月组织目录、按交易日写文件：`<canonical_root>/year=2026/month=202603/20260311.parquet`。不额外生成月度副本，也不长期复制到 DuckDB 实体表。

两层统一使用 `secu_code`，保留交易所后缀（如 `600186.SH`）。

| 字段 | 类型 | 处理与口径 |
| --- | --- | --- |
| `secu_code` | `VARCHAR` | 由 `ts_code` 重命名 |
| `trade_time` | `TIMESTAMP` | 解析源字符串；上海本地时间，保留供应商 bar 时间标签 |
| `trade_date` | `DATE` | 从 `trade_time` 派生 |
| `open/high/low/close` | `DOUBLE` | 未复权价格，不降为单精度 |
| `volume` | `BIGINT` | 由 `vol` 重命名；本 bar 成交量，单位为股 |
| `amount` | `BIGINT` | 本 bar 成交额，单位为元。**已决策**：实测源值为带二进制噪声的浮点（如 `55929077.10000002`），dbt staging 显式四舍五入到元——这是明确口径而非静默舍入；舍入前检查非负，舍入后检查不溢出 |
| `extracted_at` | `TIMESTAMPTZ` | API 响应获取时生成，以 UTC 展示；随缓存保存，dbt 重跑不改变 |

`freq` 校验为 `1MIN` 后不再存储。历史文件无法确定原始抓取时间时，`extracted_at` 允许为空，不用导入时间冒充。

Canonical 固定字段类型、单位和基础行情口径；消费 view 不再承担原始时间字符串解析等基础清洗。转换不应主动减少记录：canonical 保留全部 bar（含 09:30 竞价 bar 与午间填充 bar）。暂不引入 `pre_close`、`change`、`pct_chg`。

## 消费 view 与无效行过滤（已决策）

默认分钟 view 暴露 canonical 字段，并派生：

| 字段 | 类型与含义 |
| --- | --- |
| `bar_time` | `TIME`，`trade_time` 的时刻部分 |
| `date_int` | `INTEGER`，`YYYYMMDD` |
| `time_int` | `INTEGER`，`HHMM`，例如 `930`；不是分钟序号 |

便利用列不额外物化。默认 view 只保留**连续竞价时段**的记录：`bar_time ∈ (09:30, 11:30] ∪ [13:01, 15:00]`，即排除：

- 时间标签为 `09:30:00` 的开盘集合竞价 bar（按时间标签排除，不是删每天第一条）；
- 午间填充 bar（实测 11:31–12:59 时段存在机械重复前一根量价的不规则填充 bar）。

该过滤规则是**当前源的实测口径**，不推广为普遍市场规则。过滤只发生在 view；canonical 全量保留。需要全部 bar 的消费方（开盘竞价特征、填充 bar 分析）直接读 canonical 或加轻量专用 view，不经过默认 view。

默认分钟 view 仍包含 15:00 收盘 bar，不称为"纯连续竞价表"。收盘竞价特征结合市场和历史规则识别；上交所股票自 2018-08-20 实施收盘集合竞价，不能将更早的最后一根自动视为收盘竞价。正常完整日 241／240 根是当前源口径下的预期（填充 bar 使实际行数 241–281 不等），不强行推广到全部历史和异常交易日。

## dbt 检查

检查优先限定本次处理日期，不重复扫描全历史，也不在各层重复相同校验。

| 位置 | 检查 |
| --- | --- |
| 抓取流程（A 类） | 请求/分页按协议终止、响应有效、raw 与 manifest 落盘成功 |
| raw → canonical（B 类） | 必需字段与 `freq`、类型转换成功（含 amount 舍入规则）、`(secu_code, trade_time)` 唯一、代码和日期符合请求范围、OHLC 关系及量额非负 |
| 发布阶段 | 文件可读取、交易日与路径一致、输入输出行数与 manifest 对账、正式发布成功 |
| 消费 view | 少量样例验证派生字段与无效行过滤规则 |
| 日频特征 | 证券／日期主键唯一、所需 bar 存在；缺失时保留空值或质量标记，不用其他 bar 替代 |

不静默丢弃异常记录、不任意挑选冲突重复记录、不通过补行或删行凑齐预期 bar 数。检查失败的批次保留 raw 供处理。

初版阻止发布的检查：必需字段或固定频率不符、类型转换失败、amount 舍入后溢出或为负、必需字段为空、价格为 NaN/Infinity、主键冲突、代码或日期超出请求范围、转换前后行数不一致、输出文件不可读或日期与路径不一致。

量额非负和 OHLC 高低关系合并为简单行情合理性检查，异常先阻止发布并检查样例；若供应商存在合法特殊表达，再明确调整规则。不强制每证券每天固定 bar 数、不要求分钟与其他来源日线量额完全一致、不要求所有价格大于零。零分母由相应特征计算处理。

## 发布与审计

- 按日生成候选文件，检查通过后在同一文件系统内替换正式日文件，再登记成功；失败时保留已有正式数据和原始缓存。候选文件位于正式读取路径之外，避免被通配符提前读取。
- 允许有限批次的临时空间，不构建全历史第二份副本。V1 仅允许单个写入任务。
- 同日重跑替换而非追加；日频结果按日期替换，避免源记录减少后残留旧结果。
- Parquet 发布与 DuckDB 审计登记不视为同一事务。若文件替换后、登记前退出，重跑须核对文件并恢复登记，或安全重做当天。Canonical 已发布而特征失败时，从已发布数据补算特征，不必重新下载。
- 日频特征由 dbt 增量写入 DuckDB，支持指定日期范围重算和替换（覆盖新增、源修订和特征回填），不能仅依赖最大日期追加。

DuckDB 审计表一行表示一个交易日的一次处理尝试，由 ingestion 维护：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `run_id` | `VARCHAR` | 本次尝试唯一标识 |
| `trade_date` | `DATE` | 目标交易日 |
| `raw_path` | `VARCHAR` | 本次使用的缓存目录，包含请求清单 |
| `stage` | `VARCHAR` | 最后成功阶段：`started / fetched / published / featured` |
| `started_at` | `TIMESTAMPTZ` | 本次尝试开始时间 |
| `finished_at` | `TIMESTAMPTZ` | 尝试结束时间，成功或失败均填写；中断时可能为空 |
| `raw_rows` | `BIGINT` | 完整抓取后的记录数，未完成时为空 |
| `canonical_rows` | `BIGINT` | 发布的记录数，未发布时为空 |
| `transform_version` | `VARCHAR` | 可追溯的转换和特征代码版本，例如 Git commit |
| `error_message` | `VARCHAR` | 失败原因，成功为空 |

失败时保留最后成功的 `stage`，通过 `error_message` 表达错误。未提交的代码修改不能冒充干净的 Git commit。

## 恢复

1. 重跑以交易日为单位：读 manifest 切片状态，只重取未完成切片（成功切片的 raw 已落盘，不重复请求）。pending 切片下一次运行直接重试——服务端补数可能已完成，重访通常是一次缓存命中。
2. 同日重跑替换而非追加；已完成切片若需重取，整切片替换。
3. 发布阶段失败：保留已有正式日文件与全部 raw，修复后从候选生成继续，不必重新下载。
4. canonical 已发布而特征失败：从已发布数据补算特征。

## 历史数据

- **网盘历史**（截至 2026-04-17 的年度 Parquet）：一次性脚本按批次对齐并验证 → 候选 → dbt 检查 → 发布，不建立长期历史适配框架，不要求全量双份并存。`extracted_at` 无法确定时允许为空。
- **API 补历史**：同一接口形态，按证券 ≤7 个连续交易日一段（约 ≤2100 行，留 5000 单页余量），窗口起止对齐每日 `09:30:00/15:00:00`。跨日窗口会纳入窗口内的盘前/盘后填充 bar，落盘前按 `trade_time` 逐行校验并裁剪到各日紧窗。历史深度（官方声称 10 年以上）与补数等待未验证，首批补历史前需小范围复测。

## 未验证事项

1. **当日数据完整时点与事后修订未知**：需要数日观察（同一交易日多次重取对比）才能定刷新窗口；建议每日抓取安排在收盘后较晚时点，并对当日数据保留次日重取窗口。
2. **历史深度与退市主数据**：官方声称 10 年以上历史未实测；D 列表已完成三交易所计数闭合和有限公告抽样，但全历史覆盖仍无法由抽样证明。L→D 的日内快照翻转时点也尚未前瞻观察。
3. **供应商行为无承诺**：`stk_mins` 省略 `fields` 时的返回字段集合、填充 bar 是否随时间被上游修订，均属未知。
