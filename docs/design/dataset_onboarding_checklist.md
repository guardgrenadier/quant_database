# 新 Dataset 接入前确认清单

每个新 Dataset 单独创建 `docs/design/<dataset>_ingestion_proposal.md`，记录以下事项的结论、证据、待确认项及首版边界。本文件只维护通用清单，具体方案写入各 Dataset 自己的文档。

架构和接口以[核心架构](core_design.md)、[当前实施契约](ingestion_v3.2_implementation.md)为准。

| 方面 | 需要事先明确的内容 |
|---|---|
| 业务事实与边界 | 一行代表什么；属于快照、每日集合、事件还是有效期记录；Canonical 保存哪些事实，哪些派生留给 Serving。 |
| Schema | 字段、类型、可空性、枚举、单位/币种、日期与时区语义；区分业务时间与抓取时间。 |
| Record Key | 记录的业务唯一键；同键重复或冲突如何处理。 |
| 输入与 Scope | 允许的参数与目标范围；市场、资产、历史及未来边界；如何区分应处理、合理排除和未知范围。 |
| 上游依赖 | 范围判断所需的已发布 Dataset、Unit 和版本；缺依赖如何处理，哪些排除决策也使用了上游版本。 |
| Publication Unit 与写入政策 | 最小独立验收、完整替换范围；重跑删除哪些旧记录；请求分片与发布 Unit 的关系。 |
| 零行与缺失语义 | 无记录可能意味着什么；完整零行是否允许发布、清除旧数据并形成成功 Coverage；如何处理未发布或供应商不覆盖。 |
| 获取与完整性证据 | 请求参数、显式字段、分片、分页、上限、终止条件及限频；如何发现截断、过滤失效和范围越界。 |
| 准备与标准化 | 字段映射、解析、类型转换、空白/NULL 处理；原值保留、转换错误诊断及其 Unit 归属。 |
| 验收规则 | ERROR/WARNING 的具体规则与影响范围；源交付规则归 Adapter，标准业务规则归 Dataset，由统一 Validator 形成发布许可。 |
| 更新与修订口径 | 数据可用时点、当日终态限制、历史修订及重抓预期；成功发布的保证边界。 |
| 入口与验收证据 | CLI 参数、结果与退出状态；必要的真实样本重放、故障测试和独立库验证；消费者如何结合 Coverage 解释缺失。 |

原子发布、失败保护旧成功数据、依赖版本复核、审计和证据生命周期沿用现有内核；新切片验证其接入正确。获取完成、标准化成功、验收通过和发布成功分别表达，不能从有行或零行反推成功。

每项契约应区分供应商文档声明、真实探查结果和项目主动选择。未确定的业务语义明确列为待决项；涉及冻结架构或共享接口的变更，按 [AGENTS.md](../../AGENTS.md) 先确认。
