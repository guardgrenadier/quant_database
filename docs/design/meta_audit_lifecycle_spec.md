# Meta 审计改进 Spec

日期：2026-10-29。状态：**已实现，验证结果见文末**。

依据：[核心架构](core_design.md)、[当前实现契约](ingestion_v3.2_implementation.md)。本文记录本次确认的增量设计及实现边界。

## 1. 目标与范围

解决三项问题：进程中断留下 RUNNING / PENDING；获取或解析失败引发误导性的连带报错；执行明细无限积累。

继续采用阶段性审计、现有七张 Meta 表和发布事务。正式 ingestion 不开启 `keep-artifacts`；本次不调整 walkthrough 导出。

## 2. 中断收尾

### 触发与依据

沿用单进程写库、运行期间持续持有数据库连接的约定。独立 CLI 成功取得读写连接后，在登记新 Run 前收尾遗留 RUNNING；也允许独立维护入口只执行收尾。不能在任意 Runner 调用或只读访问中触发，不能根据运行时长判断进程死亡。

以已提交的 Meta 为依据，不从 Canonical 行数、Raw 或请求证据猜测发布结果，不恢复请求或自动发布。旧运行重跑使用新 run_id。

### 状态处理

| 对象 | 收尾规则 |
|---|---|
| PUBLISHED Unit | 保留成功状态、版本及行数 |
| FAILED Unit | 保留原始错误和阶段 |
| UNKNOWN / OUT_OF_SCOPE Unit | 保留范围决策与原因 |
| PENDING Unit | 转为 FAILED，记录执行中断；保留最后已记录阶段，不推测实际中断位置 |
| PUBLISHED Coverage | 不回退、不改写成功指针 |
| 非成功 Coverage | 按相关执行的最终状态收尾，旧 Run 不得覆盖更新的执行结果 |

中断作为 Run 级执行错误记录：没有成功 Unit 时为 FAILED，已有成功 Unit 时为 PARTIAL。即使全部 Unit 已发布、仅 Run 汇总未完成，也按 PARTIAL 收尾，Unit 成功事实保持不变。该口径沿用现有全局异常汇总语义。

每个 Run 的 Unit、Coverage 和 Run 汇总在一个事务内完成，重复执行安全。新增 `reconciled_at` 记录收尾时间；此时 `finished_at` 表示审计关闭时间，不代表准确的进程死亡时间。正常结束的 Run 不重新计算业务结局。

收尾不删除遗留证据，也不补造未入库的请求或检查。数据库连接只能证明旧写库执行已退出，孤儿 worker 治理不属于本次 Meta 收尾范围。

## 3. 连带报错抑制

原则：**判断所需输入完整且相关解析成功，才执行依赖这些输入的检查。前提不成立时保留根因及影响范围，不生成连带业务冲突。**

首轮修改银河分钟 Adapter，直接复用响应状态、请求类型、请求归属及现有解析失败分支，以局部集合限定检查范围。

| 检查 | 前提 |
|---|---|
| 快照缺席 | 由获取阶段交付错误表达，不再追加 snapshot.missing |
| 零竞价 | 对应快照完整交付，相关解析成功；明确历史不可得仍按现有专属语义处理 |
| 日线冲突、空交付歧义 | 对应 K 线完整交付，相关解析成功 |
| 竞价守恒、扣减结果 | 对应 K 线及竞价输入满足该规则的可用条件 |
| 已返回记录的坏值、越界 | 保留可独立执行的检查，不因另一输入失败而整体跳过 |

K 线与快照分别判断前提，不能仅因整个 Unit 已失败就停止所有检查。完整且可解析的空 K 线与正成交日线冲突，仍必须报错；合法零竞价、历史不可得和请求失败继续区分。

Validator 仍独立要求交付 COMPLETE、无阻断错误及业务验收合格。未执行检查不能成为放行依据；缺少具体根因时，保留现有交付门禁诊断。

不改变共享 Check 模型，不引入规则依赖图、检查注册器或逐项 SKIPPED 日志。本轮不做通用告警合并或告警级别调整。

## 4. 明细留存与退出

`coverage`、`publication`、`run`、`run_dependency` 长期保留。仅 `run_unit`、`request_attempt`、`validation_check` 按 Run 整体退出，避免拆散 Unit 对请求、检查的引用。

| Run 结束后的时间 | 明细状态与处理 |
|---|---|
| 未满 60 天 | ONLINE，保存在数据库 |
| 满 60 天、未满 365 天 | 允许归档为 Parquet，删除在线明细，转为 ARCHIVED |
| 满 365 天 | 允许归档明细过期，转为 EXPIRED 并清理文件 |

期限从 `finished_at` 起算，中断 Run 从收尾关闭时间起算；365 天是总留存期限，不是归档后再留一年。维护按到期条件处理，不要求在到期瞬间执行。

成功、失败、部分成功采用相同政策；RUNNING 不进入候选。重要故障样本需要长期保存时单独留存，不引入 `audit_hold` 或故障解决状态。后续重跑成功不改写旧 Run，也不提前清理其明细。

Run 原始 summary 不重算，仍表达执行当时的计数。追溯承诺为：发布版本、运行结局和上游依赖长期可查；逐 Unit 过程、请求和检查详情保证有限期留存，过期后不再承诺可查询。

### 维护执行

通过独立维护入口执行，默认预览候选 Run 和明细数量，显式应用后修改；ingestion 不附带历史删除。归档和过期共用现有单进程写库约束，采用普通函数实现。

归档顺序：导出三张明细表 → 校验文件可读、Schema、行数及摘要并保存清单 → 放到最终位置 → 在数据库事务中删除在线明细并登记 ARCHIVED 和路径。文件失败不删在线记录；文件已就位而数据库尚未提交时中断，重试核对已有归档后继续。

过期顺序：数据库事务标记 EXPIRED → 删除归档文件。EXPIRED 表示不再承诺明细可用；路径仍保留，用于删除失败或中断后的重试。ARCHIVED 文件意外缺失必须报告，不当作正常过期。不提供自动归档查询服务，需要时直接读取 Parquet。

## 5. Meta 字段变更

仅在 `meta.run` 新增三列，不新增表：

| 字段 | 类型 / 默认值 | 含义 |
|---|---|---|
| reconciled_at | TIMESTAMPTZ，NULL | 中断收尾时间；正常运行保持 NULL |
| audit_state | VARCHAR，NOT NULL，默认 ONLINE | ONLINE / ARCHIVED / EXPIRED，独立于 Run 业务结局及 artifact_status |
| audit_archive_path | VARCHAR，NULL | 归档目录；ARCHIVED 必须有值，EXPIRED 保留路径供清理重试 |

不借用 artifact_status 表达 Meta 归档状态；该字段继续描述 Landing 产物。沿用现有 Schema 兼容性检查，不自动修改或清空已有验证库。

## 6. 实施与验收

分两批：第一批实现中断收尾及分钟连带报错抑制；第二批实现 60 天归档、365 天过期及独立维护入口。涉及 CLI、Audit、Meta Schema/兼容性声明、银河分钟 Adapter 和必要测试；不改变 Publisher 事务、Unit 粒度或依赖版本语义。

必要验收：

1. 发布提交前、提交后至 Run 汇总前分别强制中断：无半套发布，旧版本受保护，已提交成功保持，收尾结局符合约定。
2. 收尾重复执行或再次中断可重试；旧 Run 不覆盖更新的 Coverage，正常结束的 Run 不被重写。
3. 获取或解析失败不产生依赖它的连带错误；完整空交付的真实冲突、另一成功输入上的独立错误仍可检测；失败范围不被误放行。
4. 60 / 365 天边界、RUNNING 排除及三表整体退出正确；长期保留表与 Run summary 不受删除影响。
5. 归档写入失败、归档提交前中断、过期文件删除失败均可安全重试；明细状态能区分在线、归档和过期。

本次不实现实时日志、心跳/PID 管理、自动续跑、故障工单或重跑关联、孤儿 worker 治理、通用规则框架、归档查询服务及自动数据库压缩。

## 7. 实现入口与验证

独立 CLI：`meta reconcile --db <已有库>` 仅收尾；`meta retain --db <已有库>` 预览，添加 `--apply` 执行。默认归档目录为数据库同目录的 `<库名>.audit/`，可通过 `--archive-dir` 指定。维护不加载供应商凭据，不创建业务表；旧 Meta 布局明确拒绝，不自动迁移。

实现集中于 `core/audit.py` 的收尾函数、`core/maintenance.py` 的普通归档/过期函数和 CLI 装配；三个新增 Run 字段通过正式 DDL 与兼容性声明维护。分钟检查仅在原 Adapter 内限定适用范围，未改变共享 Dataset / Adapter / Check 接口或 Publisher 事务。

专项测试使用临时数据库与离线输入，真实杀死子进程验证提交前回滚及提交后保留，覆盖重复收尾、更新 Coverage 保护、60/365 天边界、空明细归档、归档事务失败、删除失败重试及无凭据维护入口。分钟测试覆盖根因保留、独立检查与真实空交付冲突。未调用供应商接口，也未修改现有验证库。

2026-10-29 验证：全套 132 项测试中 131 项通过、1 项既有股票真实样本缺失跳过；环境烟测通过正式 DDL、业务键约束、Arrow/Parquet 往返与 dbt View 检查。
