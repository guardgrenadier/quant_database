# 银河证券接口探查 Agent Prompt

你负责探查本项目新获得的银河证券 AmazingData / tgw 数据接口，为后续正式接入提供可信依据。请自主选择调查方法、实验顺序和工具，主动追查异常与文档未说明的行为，不要停留在登录成功或取到样本。

## 项目背景

先阅读 `AGENTS.md`、`README.md`、`docs/design/core_design.md`、`docs/design/ingestion_v3.2_implementation.md` 和 `vendor/galaxy/README.md`，按需查看现有代码与研究报告。

本项目建设面向量化研究和回测的数据仓库。目前通过 Tushare 接入股票基本信息、交易日历和停复牌数据；银河 SDK 已安装，尚未正式接入。

数据链路为：获取及证据 → 标准化 Candidate → 统一验收 → 原子发布。获取成功不等于数据完整或验收通过；必须区分合法空数据、请求失败、截断和未知，失败不能覆盖旧成功数据。规划中的股票分钟数据以“一只股票 × 一个交易日”为发布单元。

本地还保存了 2010–2026 年部分历史分钟 Parquet，可用于重叠期对照，说明见 `docs/research/historical-parquet-survey-2026-09-29.md`。现有 Tushare 探查可以参考，但其限制和语义不能直接套用到银河。

## 任务

围绕本项目的实际用途，详细调查：

- **使用方法与能力**：环境、登录和会话、权限、参数、返回结构、数据覆盖。优先股票历史分钟行情及其所需的证券信息、日历和交易状态，其次日线、复权、指数成分与权重。
- **数据语义与完整性**：时间标签、量额单位、复权、停牌和无成交、竞价与盘后；如何判断完整交付，如何识别截断、部分失败、空响应、缓存旧数据和历史修订。
- **失败模式与接口限制**：错误如何暴露、是否隐藏部分结果、超时与恢复方式，以及请求容量、频率、并发、查询时段、历史范围和流量额度。
- **接入适配性**：哪些能力能满足当前架构，哪些存在缺口；提出请求组织、交付判据、标准化和验收建议，列出需要用户确认的接口或业务语义决策。

请结合官方资料、SDK 实现和真实调用建立证据。对关键行为设计对照实验，主动调查不一致结果。可以编写探针并保存样本，但本轮不实现正式接入、不修改冻结架构或正式数据。保护凭据和原始数据，仅开展数据查询，不执行交易或账号变更，不以耗尽额度的方式测试上限。

## 验收标准

1. 提供可复现的最小调用示例，以及本项目相关能力、覆盖范围和限制的清单。
2. 能回答如何获取并判断一个股票交易日的分钟数据完整；若无法可靠判断，明确缺失证据、风险及接入阻断条件，不能用“调用成功”代替完整性证明。
3. 说明关键字段与时间、单位、复权、空值语义，并用代表性正常和边界样本验证；批量与拆分获取至少完成一次一致性对照。
4. 交付失败模式与限制清单，区分实测、官方声明、SDK 实现证据、推断和未验证项，不将样本可用范围宣称为接口最大能力。
5. 对可取得的重叠样本完成历史数据或同源日线交叉核对，解释差异；无法核对时说明原因和影响。
6. 交付中文报告、可复跑探针及脱敏证据索引。关键结论能追溯到具体实验或资料，失败实验也保留记录。
7. 最终明确：哪些能力可以进入接入设计，哪些仍被阻断，下一步最值得补查什么，以及哪些决策需要用户确认。未知可以保留，但必须说明原因和实际影响。

自主推进到上述交付完成；遇到局部阻碍继续其他调查，不为常规实验选择反复请求确认。
