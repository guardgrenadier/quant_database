# 银河快照分钟重建：归桶算法比较（2026-10-23）

状态：**方案储备的研究证据，不作为当前接入方案或实施授权。** 2026-10-23 用户要求撤销本次会话对分钟接入提案的修改，讨论成果集中保留于[快照重建方案储备](../design/stock_1min_snapshot_reserve.md)。会话中曾认可切换方向和常规分钟右闭归桶，此处仅记录储备路线的讨论历史；价格、阶段边界、Schema 与验收未冻结。本文的归桶比较仅离线研究，未请求供应商、修改原始数据或实现正式 ingestion。后续更大样本及补充请求情况见[边界核查](snapshot-minute-boundaries-2026-10-23.md)。

## 1. 当前建议

采用相邻真实快照的累计量额、笔数差分，按明确的分钟边界聚合；当前样本更支持**右闭区间、左端标签**，不建议把原始时间统一前移 3 秒作为默认规则。原始时间始终保留，边界规则仅计算分钟键。

内部分钟标记 B，对应快照更新区间 `(B, B+1min]`。例如 10:01:00 的更新归 10:00，而 10:01:01 归 10:01。统一减 3 秒会把后一条也归入 10:00。这是采样更新归属契约，不能称为真实逐笔成交时间的恢复或固定传输延迟校正。

对股票、交易日内排序后的真实快照 i：

```text
delta_volume[i] = cumulative_volume[i] - cumulative_volume[i-1]
delta_amount[i] = cumulative_amount[i] - cumulative_amount[i-1]
delta_num_trades[i] = cumulative_num_trades[i] - cumulative_num_trades[i-1]
```

量额笔数使用相同边界。常规内部分钟的和，等价于在分钟两端分别取不晚于边界的最后累计值，再作差；这个等价关系不构成取到的旧快照足够新或交付完整的证明。禁止先按分钟分组再对组内快照做 diff，以免丢掉每分钟第一条增量。

首个快照不能无条件与零作差。竞价锚点、开盘首条、上午末条、午休后的基准和收盘竞价均需独立定义。当前实验没有替这些边界制定规则；旧分钟方案的竞价包含关系也没有自动改动。

## 2. 真实样本对照

输入为 2026-09-03 六股的已存快照和用户提供的逐笔聚合权威分钟参考。选取 09:31–11:28、13:01–14:55 共 233 分钟/股，避开交易阶段边界，合计 1,398 个分钟。金额对照统一到整数分，消除 SDK 浮点表示误差；不代表未来正式金额精度已确认。

| 方法 | 量、额、笔数三字段全部一致 | 成交笔数一致 | 桶合计零但权威有成交 | 权威零但桶合计正量 |
|---|---:|---:|---:|---:|
| 原时间，左闭右开 | 510 / 1398 | 554 / 1398 | 4 | 3 |
| 右闭区间、左端标签 | 718 / 1398 | 763 / 1398 | 0 | 0 |
| 整体前移 3 秒，左闭右开 | 691 / 1398 | 731 / 1398 | 0 | 0 |

两只稀疏股票 `002168.SZ`、`600365.SH` 合计 466 个分钟，在右闭和减 3 秒两种方法下三字段均 466 / 466 一致。这不是全部市场、日期或特殊状态的保证，也没有验证 OHLC。

右闭实验用减 1 微秒计算桶键，以表达整分钟边界归前桶；正式实现可直接使用原生右闭分组，无需修改时间列。该结果用于选择候选边界，不以提高精度重新定义用户的切换目标。

实验中的“桶合计零”只是没有增量被归到该桶，不等于已证明无成交。此前[零成交认证实验](../../data/probes/snapshot-zero-minute-20261023/summary.json)使用包围整个分钟的前后快照，要求量额笔数不变；在 1,422 个分钟中确认 229 个，全部与权威参考一致。两次实验范围与判定标准不同，不可将本次的 254 个零桶当成更强的独立认证。

## 3. 稀疏快照的处理边界

不补齐每个 3 秒时间点，不把量额按缺口长度均摊，不把后续正增量回填到无证据的分钟。计算只需相邻真实快照，非等间隔不妨碍累计差分。

- 两个有效快照包围整个目标分钟，累计量额、笔数均未增加：在累计值忠实反映时间、无重置或修订的前提下，可确认零成交；中间无快照也不必判缺失。
- 稀疏区间有正增量：按右闭时间桶分配可形成采样口径的候选 bar，但不证明全部成交真实发生在该分钟。若缺口跨多个分钟且交付机制不明，不能据此将其他分钟认证为零成交。
- 缺少基准或尾部证据、计数回退或字段冲突：不能通过填零或取绝对值掩盖；影响范围及是否阻断整股票日留待正式验收契约确认。

[上证所信息网络历史数据说明](https://www.sseinfo.com/services/assortment/historical/)明确描述相同相邻快照只保留第一幅，说明稀疏可能来自合法压缩；它不是银河接口完整性或压缩规则的保证。银河是否删去无变化快照、响应结束如何证明完整、是否有缺包信号，仍需供应商证据。不能只用间隔大于 3 秒判缺失，也不能只用日总量守恒证明分钟归属完整。

停牌状态继续由 suspend_daily 与快照证据联合解释，零成交不单独意味着停牌。部分分钟停牌和集合竞价等待期不得机械转换成整分钟停牌。

## 4. 候选 bar 的字段构造（待确认）

后续原始数据核查发现：仅使用 last 会遗漏可由日内极值更新补充的信息；零成交价格正在讨论按已知价格延续的口径。下列内容是第一轮建议，不作为当前冻结规则；修订建议及真实反例见[边界核查](snapshot-minute-boundaries-2026-10-23.md)。

- `volume/amount/num_trades`：同一桶内累计差分求和；num_trades 保持整数，不按时间均摊。
- 正量分钟的 OHLC：使用该桶内具有正成交增量的快照 `last` 的 first/max/min/last，定义为采样成交价格。价格未变但量增加仍参与；仅盘口变动、无成交增量的旧 last 不用于生成成交 OHLC。快照的日内 open/high/low 不直接当作区间 OHLC。
- 已确认零成交分钟：量、额、笔数为 0；建议成交 OHLC 为 NULL。若希望沿用上一价格，须明确是另一个价格表达约定，不能暗称当分钟发生了该价格的成交。
- 证据不足：未知不能写成数值 0；状态如何进入 Schema 或审计、是否阻断整日尚未确定。

旧 Schema 的 volume/amount > 0、OHLC NOT NULL 及缺少 num_trades 与新目标不兼容，必须修订后再实现；本文没有冻结新 DDL 或新增共享接口。

## 5. 性能与复现

数据已经按股票/日/时间排序时，差分、分组与分钟边界扫描可用列式计算实现，处理规模为 O(N+M)，N 为实际快照数、M 为目标分钟数；需要排序时另有 O(N log N) 成本。无需扩大成完整 3 秒网格。三种时间归桶本身均为线性运算，减 3 秒没有算法复杂度优势；本轮没有做生产性能基准。
