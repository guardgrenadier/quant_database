# stock_basic 与 suspend_d 接口实测报告

> 实验日期：2026-10-13 17:09–17:47（Asia/Shanghai，盘后）。实测接口为 ProMax 网关（`https://pcd.mobcvb.cn/tushare/pro`）的 `stock_basic` 与 `suspend_d`，对照 `trade_cal`。API Key 只从本地 `.env` 读入并用于 `X-API-Key` Header，未写入任何文件。证据（原始响应 JSON + 逐请求脱敏日志）在 `research/basic-suspend-api/tmp/`（已由 `.gitignore` 的 `research/*/tmp/` 忽略）；探针与分析脚本为 `research/basic-suspend-api/probe.py`、`analyze.py`。

预算与执行：全程顺序请求，相邻请求间隔 ≥0.35s（脚本强制），共 **56 次 HTTP 尝试**（预算 ≤100）：51 次 200、1 次 400、1 次 429、1 次 504、2 次传输层失败（连接重置/SSL EOF）、另有 7 次收到 200 响应头后读超时（客户端 30–120s 超时，重试即成功，计入 200 统计）。耗时最小 169ms、中位约 4.9s、最大 157.9s。429 一次，按退避重试成功；未出现连续 5xx 风暴。

下文区分：**【实测】**本次观察到；**【文档】**官方或手册规则；**【推断】**由实测归纳；**【未知】**本次未验证。已知事实（2026-09-19/21/23 三轮）不再重复验证，与本次冲突处单独标注。

## 1. stock_basic

### 1.1 调用方式与信封【实测】

- 端点 `GET /tushare/pro/stock_basic`；业务筛选（`list_status` 或 `ts_code` 等）必须存在，否则被当作探测（见 1.4）。
- 成功信封：`{request_id, code:0, msg:"ok", data:{fields, items}, api_name, count}`；`count == len(items)`，可即作行数。大型实时路径响应多一个 `detail:"..."` 字段（字面字符串三点，含义【未知】）。
- 空结果形态：`code:0, count:0, data:{fields:[...], items:[]}`，`request_id` 为空串。
- 探测形态（无业务筛选时）：`code:0, count:5, meta:{probe:true, local:true, sample:true, requires_params:false}`，返回 5 行本地样本且**类型退化**（`symbol`、`list_date` 变成整数）。判断请求是否被降级成探测：看 `meta.probe`。

### 1.2 字段【实测】

不带 `fields`（`list_status=L, limit=3`）返回 **15 列**：`ts_code, symbol, name, area, industry, fullname, enname, cnspell, market, exchange, curr_type, list_status, list_date, delist_date, is_hs`——与官方文档字段一致。生产建议固定 `fields`（本次用 8 列：`ts_code,symbol,name,exchange,market,list_status,list_date,delist_date`），分页时字段集合才稳定【文档：2026-09-19 已知省略 fields 时分页字段数漂移】。

类型：日期为 `YYYYMMDD` 字符串或 `null`；`market` 为中文板块名（主板/创业板/科创板/北交所），存在 1 个 D 行 `T600018.SH` 的 `market=null`。

### 1.3 行数与对账（2026-10-13 盘后快照）【实测】

| 查询形态 | 行数 | 说明 |
| --- | ---: | --- |
| `list_status=L` 分页 limit=5000 | 5000 + 573 = **5573** | 页间零重叠、零重复 |
| `list_status=L` 单页 limit=20000 | **5573** | 与两页集合逐代码相等 |
| `list_status=L` 按 exchange | SSE 2320 + SZSE 2904 + BSE 349 = **5573** | 三组并集与全量 L 逐代码相等 |
| `list_status=D` 按 exchange | SSE 147 + SZSE 187 + BSE 5 = **339** | 与 2026-09-23 相同 |
| `list_status=D` 不带 exchange | **339** | 逐代码等于三交易所并集、等于全状态 D 子集、字段值零不一致；**行为已变化**：2026-09-19/23 同形态曾返回 200/0 行假空 |
| `list_status=P` / `G` | 0 / 0 | 与全状态的 P=0、G=0 一致 |
| `list_status=UN` 单独查询 | **0（假空）** | 全状态响应中 UN=8；**单独 UN 查询当前不可信**（2026-09-23 时曾与全状态一致，行为回退） |
| `list_status=L,D,P,G,UN` 单请求 limit=10000 | **5921**（L 5574 + D 339 + UN 8） | 5921 个唯一代码，无重复 |
| 省略 `list_status` + `__probe=0` + limit=6000 | **5574**（全为 L） | 上游默认 L；与全状态 L 子集逐代码相等 |

**快照漂移**：L 分页（17:16 完成）5573 与全状态（17:18 完成）L=5574 的差异全部由数据在两次请求之间变动解释：
- `301660.SZ`（N粤芯半导体，list_date=20261013）当日上市，先 UN 后 L；
- `601059.SH`、`601198.SH` 的 `delist_date` 从 null 变为 `20261019`（**退市日期提前数日出现在仍为 L 的行上**）；
- `301716.SZ` 名称 `C鸿富诚` → `鸿富诚`（次新股指针 C 前缀脱落）。

5573 个共有代码逐字段比对除上述 3 处外零不一致。结论：universe 各查询形态在逻辑上闭合并可相互对账，但**先后请求不共享同一快照**，对账需容忍已解释的时差变动，或尽量用单请求全状态快照。

### 1.4 错误与边界形态【实测】

- 裸请求（`list_status=L`，无 `fields`/`limit`）：**400** `{"ok":false,"error":"invalid_params","message":"request response estimate exceeds the limit"}`（与 2026-09 一致，仍需 fields 或 limit 之一）。
- `list_status=X`（非法枚举）：**200 + code=0 + 0 行**——静默空，不报错。客户端必须自行校验枚举值，否则非法参数会被当成合法空发布。
- 省略 `list_status`（即使有 limit/fields）：降级为本地探测（5 行样本）；加 `__probe=0` 才走真实查询（上游默认 L）。
- `limit=10000`、`limit=20000` 均被接受并完整返回（5573/5921 < limit，满足"行数 < limit 即完整"判据）；更大值未试【未知】。
- 单代码 `ts_code=000001.SZ`：支持，返回 1 行。
- 分页稳定性：第二页（offset=5000）间隔约 18 分钟重复请求，573 行逐行（顺序+值）完全一致。

### 1.5 空值率【实测】

- L 列表：`list_date` 空值 **0/5573**；`delist_date` 全 null（除快照漂移中新出现的 2 行）。
- D 列表（339 行）：`delist_date`、`list_date` 空值均 **0**；`delist_date` 范围 1999-07-12 ~ 2026-07-30。
- UN（8 行，来自全状态响应）：`list_date` 全 null（符合"未上市"语义）。

→ **半开区间 `list_date <= t < delist_date` 的 Scope Resolver 可行**：两个边界字段在 L/D 上均 100% 非空。`delist_date` 提前数日出现在 L 行上是特性而非缺陷（可提前规划退市排除）；但也意味着"L 且 delist_date 非空"的行合法存在，消费侧不要假设 L 行 delist_date 恒空。

### 1.6 对 ingestion 实现的含义

- **Publication Unit 首选单请求全状态快照**：`list_status=L,D,P,G,UN, fields=<固定8列>, limit=10000`（当前 5921 行，距上限余量约 41%）。该形态 2026-09-23 与本次均验证闭合；逐状态/逐交易所形态可作对账，但 UN 单独查询当前假空，不能作为 UN 来源。
- 完整性检查：响应 `count==len(items)`；行数严格小于 limit；`ts_code` 唯一非空；`list_status ∈ {L,D,P,G,UN}`；状态分布相对上次快照无异常骤降；跨请求对账时容忍快照漂移（当日 IPO、新挂 delist_date、名称变动）。
- 大响应延迟高：首次（缓存未命中）请求实测 16–158s，且出现 7 次"200 响应头已收、body 读超时"，**重试即快速命中缓存**——客户端超时建议 ≥180s，读超时后原样重试是有效且安全的恢复手段【实测】。
- 每日快照安排在盘后：当日上市新股在 17:16–17:20 之间已翻转为 L【实测】；盘前翻转时点【未知】。

## 2. suspend_d

### 2.1 调用方式与信封【实测】

- 端点 `GET /tushare/pro/suspend_d`；`trade_date=<单日>` 即够，**不传 `fields`/`limit` 也返回 200**（14 行）——行为已变化【文档：2026-09-19 同形态曾 400"预计响应超限"】。
- 历史日响应走"已验证范围"路径：`request_id=""`、`msg=""`，带 `meta:{pagination_applied:true, coverage_scope:"verified_event_range", history_complete:true, data_version:[<整数>], source_contract:"verified-scope-v1"}`。data_version 按数据集不同（2020-03-12 为 [140]、2000 年为 [514]、2005 年为 [402]、2026-09-18 为 [63411]）。
- 当日（2026-10-13）响应走实时路径：有 `request_id`（UUID）、`detail:"..."`、无 `meta`。两条路径的区分本身就是数据状态信号。
- 空结果：`200 + code:0 + count:0 + data.items=[]`（meta 仍在）。

### 2.2 字段与语义【实测】

返回固定 **4 列**：`ts_code, trade_date, suspend_timing, suspend_type`。**没有复牌日期类字段**——无法从本接口预知停牌结束日。

- `suspend_type`：`S`=当日停牌，**持续停牌期间每个交易日重复出现**（002731.SZ 在 2026-09 全部 21 个交易日逐日出现 S）；`R`=当日复牌，**只在复牌当天出现**（000668.SZ、300082.SZ 在 10-08~10-12 每日为 S，10-13 为 R）。省略 `suspend_type` 时 S、R 都返回（2026-09-18：S=14、R=0、不限类型=14；2026-10-13：S=13、R=2）。
- `suspend_timing`：`null` = 全天停牌；字符串为盘中临停时段，格式 `HH:MM-HH:MM`，多段以英文逗号连接（实测样例：`10:06-10:16`、`13:30-13:40,13:49-13:59`；2015-07-08 的 1348 行中 31 行带时段）。`R` 行的 timing 是否可能非空【未知】（未观察到样例）。
- **对 stock_1min Scope 的含义【推断】**：`S + timing=null` → 当日全天剔除；`S + timing=HH:MM-HH:MM[,...]` → 只剔除对应分钟窗；`R` 行当日已复牌，不应整日剔除（盘中复牌时点未知，保守可剔除复牌日或按日线/分钟实际数据为准）。

### 2.3 过滤正确性【实测】

`ts_code=002731.SZ, start_date=20260901, end_date=20260930`：21 行，全部为该代码、日期全部落在区间内（2026-09 的 21 个交易日逐日一行），无越界行——本接口日期过滤正确（对照：`stock_st` 曾出现过滤失效【文档：2026-09-19】）。

### 2.4 分页与终止信号【实测】

2020-03-12 `limit=10`：offset 0/10/20/30 → 10、10、2、0 行；页间零重叠，并集 22 行均为当日。**短页（2<10）即末页，越界页返回 200+0 行**。终止信号 = 某页行数 < limit（含 0），与 stk_mins 结论一致。

注意：该日 2026-09-19 实测为 21 行，本次为 22 行（多出 `834770.BJ`、`835857.BJ` 两个北交所代码）——**历史数据会被上游事后修订**，完整性对账需允许已解释的 retroactive 变更，或按 data_version 跟踪。

### 2.5 量级、深度与新鲜度【实测】

- 日常量级：近期交易日 14–17 行/日（持续停牌快照语义下每天都有存量停牌股，**近 4 个交易日（10-12/10-09/10-08/09-30）均未出现零记录日**）。
- 峰值样本：2015-07-08（股灾停牌潮）**1348 行**单页（S=1343、R=5，limit=5000）；2015-01-05 有 260 行。官方单次上限 5000 行【文档】，已验证大单日远低于上限。
- 历史深度：2010-01-04 有 41 行；2005-01-04 有 18 行；**2000-01-04（当年首个交易日）有 8 行**——数据至少回溯到 2000 年初。更早【未知】。
- 非交易日形态：2026-10-01（国庆闭市）、2000-01-03（元旦闭市）均 `200 + code=0 + 0 行`（带 meta）——"合法空"合同成立，但**零记录的交易日未找到样本**（6 个交易日样本均非零）【未知：是否真实存在全市场零停牌交易日】。
- 当日新鲜度：2026-10-13 的数据在盘后 17:35 已完整可得（15 行，含 2 只当日复牌）。盘前/盘中可见性、是否盘中增量发布【未知】。

### 2.6 对 ingestion 实现的含义

- **Publication Unit = (trade_date)**：单请求 `trade_date=<开市日>, limit=500` 当前足够（日常 <20 行）；历史峰值 1348 行，建议 `limit=5000` 单页 + 短页/空页终止兜底；满页时必须翻页。
- 切片计划只按 trade_cal 开市日生成；非开市日返回合法空（200+0 行），但不应为此消耗请求。
- 零记录语义：响应层面 `200+code=0+items=[]` 已验证；但"开市日全市场零停牌"无实测样本——ingestion 遇到开市日 0 行时，应要求响应带 `meta.coverage_scope=verified_event_range` 且 `history_complete=true`，否则不得按合法空发布。
- 该接口请求快（0.2–7s），远轻于 stock_basic；每日全市场 1 次请求即可。
- 与 stock_1min 的联动：002731.SZ 这类持续停牌股每日都有 S 行，Scope 排除可直接按当日 S 集合；分钟接口对停牌日返回零量骨架 bar【文档：分钟报告 §5】，两边判定可互为校验。

## 3. 网关层观察（两接口共用）【实测】

- 延迟分布极不均匀：stock_basic 大响应 16–158s，suspend_d 0.2–7s，小查询 0.2–2s。
- 7 次"200 头 + body 读超时"全部发生在 stock_basic 大响应的首次请求上，重试即快速成功（X-Cache 多显示 HIT）——首次请求似乎在网关侧继续完成并写入缓存。**X-Cache:HIT 也曾出现在读超时的响应头上，不能作为"数据已完整收到"的依据**。
- 429 一次：`{"ok":false,"error":"rate_limited","message":"response memory is busy; retry shortly"}`，**无 Retry-After 响应头**，退避后 2 分钟内成功。与配额型 429 文案不同，属服务端内存压力。
- 504 一次：`{"ok":false,"error":"upstream_pool_exhausted"}`（手册记为 503 的错误体出现在 504 上），重试成功。
- 传输层失败 2 次（连接重置、SSL EOF），均为首次请求某端点时发生，重试成功。
- `X-RateLimit-Remaining` / `X-RateLimit-IP-Remaining` 响应头本次全部未出现（手册称"以限流响应头为准"，实际只能靠 429 事件感知）。

## 4. 未解决问题

1. **suspend_d 当日数据的盘中/盘前可见性与修订窗口未知**：本次仅盘后一个时点（17:35）。需要多日、每日多时点重取对比，才能定抓取时点与是否需次日重取窗口。
2. **stock_basic 盘前快照翻转时点未知**：当日 IPO 在盘后已入 L；盘前是否已翻转（影响盘前 universe 生成）未验证。
3. **开市日零停牌样本未找到**：6 个交易日样本均非零；"开市日 0 行 = 合法空发布"的合同只有非交易日与空类型筛选的间接证据，建议 ingestion 对开市日 0 行加强校验（见 §2.6）而非直接采信。
4. **429 "response memory is busy" 无 Retry-After**：退避参数只能自定义；该错误与配额 429 的关系、是否会成批出现未知。
5. **历史数据的 retroactive 修订幅度未知**：2020-03-12 一个月间 21→22 行；suspend_d 的 `data_version` 能否用于变更检测、stock_basic 是否有类似机制，均未验证。
6. `limit` 拒绝点未探到（20000 可用）；`suspend_timing` 与 `R` 的组合、盘中临停时段与分钟 bar 的对应关系未验证（需在 stock_1min 侧对照）。
7. P/G 单独查询的 0 行无法与"假空"区分（仅全状态响应同为 0 作为旁证）；UN 单独查询假空是否为永久行为变化未知。
