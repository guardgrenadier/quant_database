# 历史分钟零成交量、停牌与占位 bar 调查（2026-10-22）

## 结论

**网盘历史分钟文件确实包含占位的零成交量 bar，且分钟行本身不区分停牌、正常交易时段无成交、集合竞价等待撮合等原因。** 停牌分钟和普通无成交分钟，都能表现为 `vol=0、amount=0、OHLC 沿用前价`。因此，保留了价格和时间槽位，不等于该分钟发生了成交，也不等于该分钟可交易。

**全天停牌没有统一的“必定补齐”或“必定无行”行为。** 网盘中同时存在全天 241 根零量占位和整只股票当日无行的情况。仅凭缺行、零量、连续平价或零量段长度，均不能可靠判定停牌。

本轮直接调用官方 `stk_mins`，确认 `000029.SZ / 2020-03-12` 全天停牌仍返回 **241 根零量、零额、固定价格 bar**，与网盘同股同日六个行情字段在 float32 精度下全部一致。这证明官方分钟接口也存在这种占位行为，但不能据一个样本推断两套数据全历史同源或完全一致。

## 调查范围与证据

- 源文件：`data/raw/stock_1min/year=YYYY/YYYYMMDD.parquet`，只读。
- 检查全部 **3,954** 个文件的列名：3,949 个带 pandas 索引列，5 个不带；均没有停牌状态、可交易状态或补齐标志。业务列是 `code, trade_time, close, open, high, low, vol, amount, date, pre_close, change, pct_chg`。
- 对每年首个文件，以及停牌/历史勘察重点日期，合计 **23 个交易日、19,933,809 行**做数值统计，其中 **1,637,380 行 `vol=0`**。这不是全历史零量占比估计，也不是全历史完整性验收。
- 在 7 个重点日调用官方 `suspend_d(trade_date=...)`，不筛选 S/R 类型；响应均成功、`has_more=false` 且低于 5,000 行。另取 `daily / 2020-03-12` 核对当日实际成交量。
- 官方分钟首个样本成功；第二个请求返回 `40203`，提示 `stk_mins` 限频 **1 次/小时**，因此停止后续分钟请求。失败不解释为零行；本轮官方分钟直接对照范围仅一股一日。
- 调查前后全部源文件大小与修改时间一致；没有写源文件、数据库或生产代码，没有修改架构、共享接口或业务 invariant。

本地证据目录：[minute-zero-volume-20261022](../../data/probes/minute-zero-volume-20261022/)。其中 `investigate.py` 是可丢弃的取证脚本，不是正式获取实现；从仓库根执行 `uv run --frozen python data/probes/minute-zero-volume-20261022/investigate.py`。已有接口证据与主统计会复用；补充核查记录另见 `additional_checks.json`。

## 全天停牌记录与分钟文件的交叉统计

以下严格称为“官方 **S 且时段为空** 的沪深股票”，不将这个条件写成项目新的全天停牌判定规则；北交所／历史映射代码不进入此表。

| 日期 | S 且时段为空 | 文件有行且全日零量 | 文件当日无行 | 文件有正成交量 |
| --- | ---: | ---: | ---: | ---: |

这些数据明确否定“停牌股一律没有分钟行”和“停牌股一律补满分钟行”。但它们没有说明供应商为什么对不同股票／年份采取不同处理，不能自行把差异解释为某项确定的补齐策略。

2010-01-04 的反例是 `000516.SZ`：官方 S、时段为空，网盘上午 121 行均有量、合计 9,521,500 股，下午 120 行全零量。因此，当前实际数据不足以支持不加例外地把 `S + NULL timing` 自动转换成“全日不可交易”。本轮只报告冲突，不更改已有 `suspend_daily` 保留原始时段、不推导可交易状态的契约。

证据：`suspension_comparison.json`、各日 `suspend_*.json` 和 `additional_checks.json`。

## 零量 bar 的填价模式与例外

主流模式是量额均零、四价不为空，并延用上一条记录的收盘价。例如 2020-03-12 全市场有 **34,475** 根零量，其中有上一条同股记录的 **34,421** 根，全部满足 `open=high=low=close=上一条 close`。剩余 54 根是各股首条记录，没有当日上一条可供比较。

但不能把这个观察升级成全历史硬规则：

- 23 日样本中，有 **216** 行 `vol=0` 但 `amount>0`，其中 2010-01-04 为 29 行、2011-01-04 为 187 行。例如 `000010.SZ / 2010-01-04 13:02`，量为 0、金额为 297 元。尚未查明是源量精度／取整还是其他问题，不能断言这些行确实没有成交。
- 其中有 **2** 行零量但四价不完全相同，均在 2011-01-04。例如 `002055.SZ / 13:07`，open/low 约 27.19、high/close 约 27.20，amount=1,904。
- 7 个重点日的上一收盘价比较也有少量不沿用前价的例外：2010-01-04 为 29 行、2018-07-04 为 2 行、2024-04-17 为 1 行；本轮未为这些行猜测填价算法。

所以，“四价固定且量额均零”是占位表现的有力线索，却不是停牌原因标记；`vol=0` 单独也不足以确认无成交。

证据：`local_stats.json`、`additional_checks.json`。

## 官方文档支持到什么程度

[Tushare 官方股票历史分钟文档](https://tushare.pro/wctapi/documents/370.md)列出价格、量额、代码、时间，没有停牌或补齐字段。其 2023-08-25 样例直接展示 14:58、14:59 的零量零额平价 bar，以及 15:00 的成交。文档没有给出全天／盘中停牌的统一补齐保证，因此本轮有关全天停牌占位的确认来自实际 API 响应，而不是对文档的推测。

[Tushare 官方停复牌文档](https://tushare.pro/wctapi/documents/214.md)提供独立的 `suspend_type` 与 `suspend_timing`，可作为区分原因的外部证据；但实际历史数据仍需考虑空时段和遗漏／冲突，不能把“名单无记录”当作已经证明全日正常交易。

分钟标签也必须先对齐。本项目已有[历史文件与银河对照](galaxy-amazingdata-interface-probe-2026-10-19.md)确认沪深网盘样本以结束分钟标记、09:30 单列开盘竞价；银河则采用开始分钟。网盘常见 241 行是“09:30 单列 + 240 个分钟结束标签”，不是 241 分钟连续竞价。盘中停牌边界可能落在有成交的一分钟内：`300819` 的 09:31 仍有 800 股，不能按官方 `09:30-10:00` 文本直接把它覆盖成零量或删掉。北交所与历史收盘机制还存在下述差异，不能直接套用沪深样本的解释。

## 补充：连续竞价范围外的标签，以及竞价 bar 是否固定

### 全量时间标签扫描

针对后续问题，对全部 **3,954 个文件、3,380,472,530 行**按原始时间标签、市场和年份做了统计，读取 `code/trade_time/vol/amount`，不是抽样。相对用户给出的标签区间 `09:31–11:30、13:01–14:57`，范围外标签只有：

| 市场 | 范围外标签 |
| --- | --- |
| 沪深 | `09:30、14:58、14:59、15:00` |
| 北交所 | 上述四个，以及部分历史日的 `15:01–15:30`，逐分钟都有标签 |

全历史没有 09:30 之前、午休 `11:31–13:00` 或 15:30 之后的标签，所有标签秒数均为 00；没有独立的 09:25 或 13:00 bar。沪深源文件没有 15:00 之后的 bar，这不能证明它们完整覆盖了市场上可能存在的盘后交易。

北交所 15:00 之后的标签出现在 **2022–2025** 年文件。它们不全是零量：全历史在 15:01、15:02、15:30 分别有 **81,282、554、1,685** 根正成交量 bar，15:03–15:29 未发现正成交量。

例如 **2024-04-17**，248 只北交所股票各有 271 行：241 个常规槽位再加 30 个晚于 15:00 的槽位。248 根 15:00 全为零量；246 根 15:01 有量；15:30 还有 5 根有量。不能依据时间标签就把这批 15:00 后记录全部删除、全部称为占位，或认定它们全部属于某一种盘后交易；其具体归属尚缺逐笔或供应商解释。

证据：`time_labels.py`、`time_labels_all_years.json`、`time_labels_summary.json`、`time_labels_sample_details.json`。

### “固定 09:30 / 15:00”要分槽位与成交含义

**作为沪深常见模板中的两个槽位，是 09:30 / 15:00；作为全历史、全市场的两个纯集合竞价成交 bar，不能这样定义。**

1. 开盘集合竞价的实际时段是 **09:15–09:25**；网盘沪深样本把其成交单列到 **09:30 标签**。标签不等于实际撮合时间，也不保证发生过成交。标准 241 槽位可拆为 `09:30(1) + 09:31–11:30(120) + 13:01–14:57(117) + 14:58/14:59(2) + 15:00(1)`。
2. 沪深实施收盘集合竞价时，网盘通常由 **15:00** 承接收盘成交。但上交所是从 **2018-08-20** 才实施 14:57–15:00 收盘集合竞价，之前沪市 14:58、14:59、15:00 仍可能是正常连续竞价分钟。因此不能用当前时段规则重新定义全部历史 bar。见[上交所原始通知](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20180806_4607055.shtml)和[深交所交易时段说明](https://www.szse.cn/www/investor/institute/rules/t20200827_581076.html)。
3. 即使在实施收盘集合竞价之后，源文件 **14:58 也不保证零量**。2024-04-17 的沪市有 424 根、北交所有 33 根 14:58 bar 带量，深市该标签全零量。它们是否属于边界成交／行情归桶延迟，尚未查明，不能假定全部是竞价等待撮合占位。
4. 北交所不能直接套用“收盘成交只在 15:00”这一源数据解释：上述 2024 样本的 15:00 全零量、15:01 大量有量。官方市场的收盘集合竞价时段仍为 **14:57–15:00**；这是源记录标签与交易阶段的映射问题，不能解释成交易所将收盘竞价延长到 15:01。见[北交所交易规则](https://www.bse.cn/jygl_list/200010919.html)。
5. 槽位本身也不能假定对每个股票日都存在：25 个样本日、89,695 个实际有行的股票日均同时有 09:30/15:00；但进一步全量检查北交所发现 **4,924 个股票日没有 09:30**。例如 `920000.BJ / 2022-08-24` 首条是 11:10，最后到 15:30，共 171 行。缺开盘段的原因尚未确定，不能猜测为正常模板或停牌。

这里关于“范围外标签集合”是全历史结论；沪深开盘竞价单列与收盘成交映射仍是源样本及既有项目研究支持的解释，没有用逐笔数据证明每根 bar 的成交组成。本轮没有新增官方分钟请求。

证据：`time_labels_sample_edges.json`、`time_labels_bj_missing_edges.json`，以及前述全量统计。

后续已对北交所 15:01／15:02 做了官方日线交叉验证，并在 2024-04-17 确认 15:30 的 5 个非零量样本对应官方大宗交易；还发现 2026-04-13 的全市场收盘附近缺口。详细证据与“能否统一平移”的判断见[北交所收盘标签专项调查](historical-minute-bj-close-labels-2026-10-22.md)。

## 对项目数据语义的含义

这是研究建议，尚未修改正式设计：分钟事实应保留源行，零量原因需要另行结合停复牌事实与交易时段解释。普通无成交、停牌、集合竞价等待撮合、来源不明／数据异常应保留区分空间，不能统一标成“停牌”，也不能从缺行自动生成零量行。

本轮已回答“是否区分、是否占位、主要如何表现”，并补充了全历史时间标签扫描。尚未完成全 3,954 日的全字段数值质量检查、逐笔级证明每个普通零量分钟确实没有成交、查清早期零量正金额原因、推定缺行的供应商内部策略，以及多股多日官方分钟 API 对照。
